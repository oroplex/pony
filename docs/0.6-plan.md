# Pony 0.6.0 — ordered milestone plan

Branch: `opus-0.6` (off `opus-0.5.1`). Package `app.pony.companion`,
versionName `0.6.0`, versionCode `7`. Work straight through, commit per
milestone, keep Android JVM tests and the Node suites green.

This plan is the contract for the work. Milestones are ordered so the
foundational harness fixes land first (they make every later feature testable
on a Galaxy S26 Ultra), then the new capabilities, then pairing, release, docs.

Guiding rules kept from 0.5.1:

- Confirm **only** on send / post / pay / buy / book / order / delete / call.
  Settings changes never confirm. `SafetyPolicy` stays the backstop.
- 30-step cap with a **Keep going** resume (`AgentLoop.MAX_STEPS = 30`).
- Unit tests for every new piece of logic. Node tests stay green.
- No keystore, API key, or secret ever committed. Release APK is **unsigned**.

Each new phone capability is one tool added in **four** places that must stay in
lockstep (map from exploration):

1. Local brain tool list + schema — `brain/AdapterRequests.tools`
   (reaches Claude, Gemini, and OpenAI-compat identically).
2. Local executor — `voice/PhoneOps.execute` → `display/ScreenRouter`.
3. Wire op — `shared/src/protocol.ts` `CommandOp`/`CommandParams`, the Android
   dispatch `session/PonySessionService.handle`, the MCP tool
   (`packages/mcp/src/server.ts` + `controller.ts`), the CLI
   (`client/src/cli.ts`), and the Node mock phone (`client/src/mock-phone.ts`).
4. Tests — Kotlin (`app/src/test/...`) for builders/parsers, vitest
   (`packages/mcp/src/mcp.test.ts`, `client/src/e2e.test.ts`) for the wire.

## M1 — Harness bugs on real freeform pop-ups

The S26 bugs all come from one root cause: on the default display Pony reads and
targets **only** `rootInActiveWindow`, but Settings/Google/Gboard open as
freeform pop-ups that are **not** the active a11y window. Fix the window model
once, in a JVM-testable helper, then route `ui_tree`, tap labelling, focus, and
foreground through it.

**M1.1 — `type` replace vs append (bug 4).**
- New pure param `append: Boolean` (wire `mode: "replace" | "append"`, default
  replace). `PonyAccessibilityService.typeText(text, append, displayId)` skips
  `selectAll` only when `append`; replace always selects-all first.
- Fix the real append cause: `focusedEditable` must search **all** windows
  topmost-first (M1.2), not just `rootInActiveWindow`, so the caret/select-all
  act on the pop-up's field, not the app underneath (`languagesvoice typing`).
- Plumb `append` through `ScreenRouter.type`, `PhoneOps`, wire, MCP, CLI.
- Tests: `TextEntryTest`/new `TypeModeTest` (selectAll decision), MCP/e2e
  `type` with `mode:"append"`.

**M1.2 — Topmost-window targeting + full bounds + window rect (bugs 1,5,7).**
- New pure helper `a11y/WindowStack.kt` over `List<WindowShot>`: `topmost(at)`,
  `ordered()` (layer desc), `bounds()` (union), excluding a11y/magnification
  overlays. Unit-tested on the JVM with fabricated `WindowShot`s.
- `PonyAccessibilityService.roots(DEFAULT_DISPLAY)` returns **all** window roots
  (topmost first) instead of only `rootInActiveWindow`; `uiTree` dumps each
  window with its package, layer, and full bounds, so the popup bottom is no
  longer clipped at y=2184 and underlying FrameLayouts don't mask it.
- `tapTarget`/`labelAt`/`focusedEditable` walk the same ordered window roots.
- Results carry the resolved `window` rect (and `windowPkg`) so a moving pop-up
  is re-resolved per call and reported: add to `ScreenRouter` result fields.
- When a window's nodes are empty, fall back to a screenshot/OCR **hint** note
  in the tree text (`(window has no readable nodes — look at the screenshot)`)
  rather than returning empty FrameLayouts.
- Tests: `WindowStackTest` (topmost at point, union bounds, overlay exclusion,
  empty-node hint).

**M1.3 — Never report a screenshot without an image (bug 3).**
- `screenshotJpeg` retries capture (up to 3) and asserts non-empty bytes; a
  zero-byte compress is a failure.
- `ScreenRouter.shot` + `PonySessionService` screenshot branch + MCP
  `screenshot` only mark `ok` when image bytes exist; otherwise explicit error.
- Tests: `ScreenshotResultTest` (ok ⇒ bytes present; empty ⇒ error), MCP test
  asserts an image content block accompanies an ok screenshot.

**M1.4 — Honor explicit `display:'background'` / `background:true` (bug 2).**
- `DisplayPolicy.choice` already resolves explicit → BACKGROUND. Thread an
  `explicitBackground` flag so `BackgroundHost.open`, when it cannot host on a
  real background display, returns an explicit **warning** result
  (`background_unavailable`) instead of silently opening freeform — unless the
  owner's fallback pref already said pop-up/allow.
- Tests: `DisplayPolicyTest` additions (explicit background returns warn, pref
  background still falls back).

**M1.5 — Hide the overlay pill during taps/gestures (bug 6).**
- Wrap every gesture dispatch (`tap`, `swipe`, new gestures) in
  `OverlayHost.passThrough { ... }` so the pill is non-touchable/hidden for the
  whole gesture, restored after — not only when `covers(x,y)` happens to be
  true. Keep the existing cover-based pass-through as a subset.

**M1.6 — `open_settings` tool + direct IME settings (scope 6, bugs 8,9).**
- New pure `intent/SettingsIntents.kt`: a **named allowlist** mapping friendly
  names → `Settings.ACTION_*` (input method, locale/languages, app details,
  accessibility, sound, display, battery, date, security, wifi, bluetooth,
  location, voice input) plus a guarded raw-action path that only permits
  `android.settings.*` actions. `appDetails(pkg)` builds
  `ACTION_APPLICATION_DETAILS_SETTINGS` with `package:` uri.
- Direct IME settings (bug 8): resolve the enabled IME's
  `InputMethodInfo.getSettingsActivity()` and launch it, instead of the
  "Select input method" picker.
- Wire `open_settings` end-to-end (local tool, executor, wire op, MCP, CLI,
  mock phone) with a `ScreenRouter.openSettings`.
- Tests: `SettingsIntentsTest` (named resolves, raw allowlist accepts
  `android.settings.*` and rejects others, appDetails uri), MCP/e2e
  `open_settings`.

## M2 — Gestures (scope 4)

- `a11y/GestureBuilder.kt` pure builder returning stroke specs for `long_press`
  (single stroke, long duration), `drag` (press-hold-move-release), and `pinch`
  (two strokes converging/diverging). Coordinates + durations only, JVM-testable.
- `PonyAccessibilityService.longPress/drag/pinch` build `GestureDescription`
  from the specs (multi-stroke via `addStroke`), dispatched through the overlay
  pass-through, on any display.
- Tools `long_press`, `drag`, `pinch` across local tool list, executor, wire,
  MCP, CLI, mock phone.
- Tests: `GestureBuilderTest` (start/end points, two-finger pinch strokes,
  duration clamps), MCP/e2e for each gesture op.

## M3 — Smart waits (scope 5)

- `a11y/SettleWait.kt` pure decision: given a sequence of (a11y-idle, screenshot
  diff ratio) samples and a timeout, decide settled / keep-waiting / timed-out.
  Screenshot diff is a cheap down-sampled byte/luma difference ratio, also pure.
- Runtime `wait_idle` uses `WindowSignal` (already emits on
  WINDOW/WINDOWS_CHANGED) for a11y quiet plus the screenshot diff, bounded by a
  timeout; returns `{settled, waitedMs, reason}`.
- Replace the fixed `Thread.sleep(700/600)` settle points opportunistically
  where a real settle check is safe; keep sleeps as floors.
- Tool `wait_idle` across the stack.
- Tests: `SettleWaitTest` (idle+low-diff ⇒ settled, busy ⇒ wait, timeout),
  diff-ratio tests.

## M4 — Memory (scope 2)

- `memory/MemoryStore.kt`: local, encrypted with the existing
  `KeystoreSecretBox` + file-vault pattern (same as brain secrets) at
  `filesDir/memory`. Entries `{key, value, source, createdAt}`.
- `memory/MemoryGuard.kt` pure redaction: never store passwords, OTPs, 2FA
  codes, card/CVV, secrets — detected by key/value heuristics. Unit-tested.
- Tools `remember`, `forget`, and read via injecting a compact memory summary
  into `AgentLoop.SYSTEM` preamble at task start (so every brain sees prefs).
- Settings → **Memory** screen: list entries, delete one, clear all.
- Tests: `MemoryStoreTest` (encrypt round-trip, not plaintext on disk, delete),
  `MemoryGuardTest` (rejects password/OTP/card, accepts a name/city).

## M5 — Natural voices (scope 1)

- Extend `VoiceCatalog`: rank **neural / enhanced / local high-quality** voices
  above legacy ones, still this-language-first; surface a readable label per

- Optional **cloud voice** behind a setting (`VoicePrefs.cloudVoice`): when on,

- Per-voice **preview** in the Voice screen (speak a sample with that voice).
- Tests: `VoiceCatalogTest` additions (neural ranked first, cloud gating).

## M6 — Scheduled tasks (scope 3)

- `schedule/ScheduleParser.kt` pure: parse "every morning at 7", "every day at
  7am", "weekdays at 8:30", "tomorrow at 18:00" → a `Schedule` (time, days,
  repeat). `nextFireAt(now)` pure. Unit-tested hard.
- `schedule/ScheduleStore.kt` JSON persistence of `{id, text, schedule,
  enabled}`.
- `schedule/ScheduleAlarms.kt`: `AlarmManager.setExactAndAllowWhileIdle` per
  next fire; `ScheduleReceiver` fires → `VoiceController.ask(text)` then reschedules;
  `BOOT_COMPLETED`/`MY_PACKAGE_REPLACED` reschedules all (manifest receiver).
- Natural-language create path: a `schedule_task` tool and/or Basics verb so
  "every morning at 7 read my calendar" creates a schedule.
- Settings → **Scheduled tasks**: list, toggle, edit time, delete.
- Tests: `ScheduleParserTest` (phrases → schedule, nextFire across midnight/
  weekday boundaries), `ScheduleStoreTest`.
